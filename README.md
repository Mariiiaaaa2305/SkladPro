# СкладPro — система управління складом

Вебзастосунок для управління складськими запасами, товарами, постачальниками, контрагентами та складськими операціями.

**Технології:** Python, Flask, MySQL, Jinja2, HTML/CSS, pytest.

## Запуск

### 1. Клонування репозиторію

```bash
git clone <URL_репозиторію>
cd warehouse_management
```

### 2. Встановлення залежностей

```bash
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

### 3. Налаштування середовища

Створіть файл `.env` на основі `.env.example` і налаштуйте параметри підключення до MySQL.

```env
SECRET_KEY=replace-with-a-random-secret
MYSQL_HOST=localhost
MYSQL_PORT=3306
MYSQL_USER=root
MYSQL_PASSWORD=
MYSQL_DATABASE=warehouse_management
```

### 4. Підготовка бази даних

```bash
mysql -u root -p < database/schema.sql
mysql -u root -p warehouse_management < database/seed.sql
```

Якщо база даних уже створена та містить початкові дані, повторно запускати SQL-скрипти не потрібно.

### 5. Запуск застосунку

```bash
python run.py
```

Відкрийте застосунок у браузері: [http://127.0.0.1:5000](http://127.0.0.1:5000).

## Функціональні можливості

- Авторизація користувачів.
- Розмежування прав доступу за ролями.
- Облік товарів і складських запасів.
- Управління постачальниками та контрагентами.
- Облік складських рухів.
- Робота зі складськими документами.
- REST API для роботи з товарами.
- Адміністративна панель для керування користувачами.
- Керування ролями та активністю облікових записів.
- Зберігання даних у MySQL.

### Ролі та права доступу

**Менеджер (`manager`)**

Має доступ до основного функціоналу складської системи:
- робота з товарами;
- робота з постачальниками та контрагентами;
- виконання доступних складських операцій;
- робота зі складськими документами;
- використання доступних функцій системи відповідно до встановлених прав.

**Адміністратор (`admin`)**

Має всі можливості менеджера, а також додаткові функції керування системою.

| Розділ | Можливості |
|---|---|
| Користувачі | Перегляд і керування обліковими записами |
| Ролі | Розмежування прав доступу користувачів |
| Активність облікових записів | Активація та деактивація користувачів |

Неактивний користувач не може авторизуватися до повторної активації облікового запису.

Самостійна реєстрація вимкнена. Нові облікові записи створює адміністратор.

## REST API

REST API забезпечує роботу з товарами за допомогою HTTP-методів:

| Метод | Призначення |
|---|---|
| `GET` | Отримання списку товарів або інформації про окремий товар |
| `POST` | Створення товару |
| `PATCH` | Оновлення інформації про товар |
| `DELETE` | Видалення товару |

Для неавторизованих запитів повертається `401 Unauthorized`. Якщо користувач не має необхідних прав для виконання операції, сервер повертає `403 Forbidden`.

Інтерактивна документація Swagger не налаштована.

## Архітектура проєкту

Застосунок побудований на Flask із використанням Blueprints для організації маршрутів, репозиторіїв для доступу до даних і сервісів для реалізації бізнес-логіки.

Основні компоненти:
- **Models** — моделі предметної області.
- **Routes** — вебмаршрути та REST API.
- **Repositories** — взаємодія з базою даних.
- **Services** — бізнес-логіка.
- **Patterns** — реалізації шаблонів проєктування.
- **Templates** — HTML-шаблони.
- **Static** — CSS та статичні файли.

## Шаблони проєктування GoF

У проєкті реалізовано такі шаблони проєктування:

- **Strategy** — дає змогу використовувати різні алгоритми через спільний інтерфейс.
- **Command** — представляє операцію у вигляді окремого об'єкта.
- **Facade** — спрощує взаємодію з підсистемами через єдиний інтерфейс.
- **Factory Method** — делегує створення об'єктів фабричному методу.
- **Simple Factory** — централізує створення об'єктів залежно від заданих параметрів.
- **Observer** — забезпечує механізм сповіщення підписників про зміни стану об'єктів.

Детальний опис архітектури та реалізації шаблонів наведено у `docs/ANALYSIS.md`.
